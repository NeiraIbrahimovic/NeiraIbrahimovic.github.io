03 · AWS security

Replacing long-lived access keys without breaking customer storage.

A technical product case study in cross-account AWS access, security migration and backward compatibility.

RoleTechnical Product Manager
ProblemCustomer-owned S3 access relied on IAM users and credentials
GoalMove toward role-based cross-account access
FocusSecurity, migration and platform behavior

The problem

What made this difficult.

Customer-owned storage configurations depended on IAM users and long-lived credentials. The product challenge was not simply to choose a safer AWS primitive. We needed a model customers could configure, the platform could assume securely, and existing integrations could realistically migrate toward.

Key product decisions

The decisions underneath the feature.

01

Use roles as the target access model

The direction moved from customer credentials toward cross-account role assumption, reducing dependence on long-lived access keys.

02

Make trust explicit

The model required a clear trust relationship between the customer account and the platform, with customer-controlled permissions around the S3 resources being shared.

03

Design migration with the architecture

Existing configurations could not simply disappear. Backward compatibility and migration behavior had to be considered alongside the target security model.

04

Account for constrained environments

VPC-only workflows and role chaining changed what looked straightforward on an architecture diagram. Those constraints had to be surfaced as product requirements.

My role & impact

Where I contributed.

I helped define the product requirements and migration strategy with engineering and security stakeholders. My work focused on turning AWS security mechanics into explicit customer and platform behavior: what customers configure, what the platform assumes, what happens to existing configurations, and where restrictions change the workflow.

Technical deep dive

What I had to understand to make the product decisions.

The work required fluency in IAM roles, trust relationships, bucket policies, role assumption, cross-account access and role chaining. The key product question was always the same: how do we improve the security posture without creating a migration that customers cannot adopt?

What I learned

A technically safer future state is only a product solution when the migration path is credible. Security architecture, configuration UX and backward compatibility have to be designed together.
